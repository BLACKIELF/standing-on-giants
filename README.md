# githubskill

一个在开始实现前，先去 GitHub 做方案侦察的 Codex Skill。

它帮助你回答一个实际问题：这个需求应该**直接使用现有项目、基于现有项目修改，还是自己开发**？

## 实际意义

很多需求一开始就写代码，最后才发现：GitHub 已经有类似项目、候选项目已经弃维护、部署依赖很重，或许可证不适合当前用途。

`githubskill` 把“先研究，再决定”固定成一个有证据的流程：

- 减少重复造轮子和过早开发
- 把“找到几个仓库”变成可执行的方案决策
- 在实施前检查维护状态、部署难度、可复用功能、改造成本和许可证
- 保留人工确认门，避免未经确认就写代码、安装或部署

## 什么时候使用

适合：

- 准备做一个工具、网站、自动化流程或本地服务
- 想先确认 GitHub 是否已有可复用方案
- 需要比较直接使用、二次开发和自行开发

不适合只收集热门仓库，或已经明确要求立即开始编码的任务。

## 它会做什么

1. 拆解目标、核心场景和 MVP 功能
2. 找少量直接相关的 GitHub 候选项目
3. 核对当前 star 数、维护状态、部署难度、可复用功能、改造成本和许可证
4. 给出唯一结论：直接使用 / 基于现有项目改 / 自己开发
5. 提供最多 5 步的最简单 MVP，并等待确认

通常只保留 3–5 个候选，证据足够就停止调研。

## 确认前的边界

在用户确认方案前，Skill 不会：

- 写业务代码或修改项目文件
- 安装依赖、启动服务或部署
- 创建或上传 GitHub 仓库
- 配置密钥或凭据

“确认方案”也不自动等于授权部署、上传或配置密钥。

## 安装与使用

将本仓库根目录作为 `githubskill` 放入支持 Skills 的目录，并保留以下结构：

```text
githubskill/
├── SKILL.md
└── agents/
    └── openai.yaml
```

刷新或重新启动支持 Skills 的客户端后，可以这样使用：

```text
使用 $githubskill，帮我做一个可以自动整理 Gmail 附件到 Google Drive 的工具。
先查 GitHub，不要写代码。
```

它会先给出候选对比、方案判断和最小 MVP，等你确认后才进入实施。

## 文件说明

- `SKILL.md`：完整研究流程、审查标准、输出格式和确认门
- `agents/openai.yaml`：显示名称、简短描述、默认提示词和调用配置

## 已知限制

- GitHub 的 star 数、提交状态、Release 和 Issue 状态具有时效性
- 结论依赖当次能够访问到的 GitHub 和官方资料
- 许可证判断不构成正式法律意见
- 研究结论不能代替真实的部署验证
- 当前 Skill 负责研究和决策，不负责自动运行候选项目或持续监控仓库
